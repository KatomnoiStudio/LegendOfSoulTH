# Task ledger audit — 2026-08-12

**Every open row in the working task ledger, measured against the repository at `9f5c666` rather than re-read and believed.**

The owner asked for this before the next release, on the grounds that carrying tasks with stale data has consequences — you spend a day on work that was already done, or you skip work because a row says it is finished. The audit found both of those in this ledger.

## How it ran

59 open rows, split into eight domain batches, one agent per batch. Every agent was read-only and was told that a verdict without a `file:line` or a command and its output is a failed verdict, not a soft one.

Then a second pass: for every row an auditor called **ALREADY-CLOSED** or **FACTS-MOVED**, a separate agent was pointed at that verdict and told to **refute it** — to re-measure by a different route, and to default to refuting when unsure. Those are the two verdicts that cost real work when they are wrong, because both look like progress.

**38 verdicts were attacked. 12 did not survive.** That pass is the reason this document is worth reading.

| verdict        | rows |
| -------------- | ---- |
| FACTS-MOVED    | 31   |
| STILL-OPEN     | 17   |
| ALREADY-CLOSED | 7    |
| OWNER-ACTION   | 4    |

`OWNER-ACTION` is not a code gap — it is blocked on a person or an external console (a Supabase Dashboard toggle, a GitHub setting, a bank, a lawyer). It is broken out from `STILL-OPEN` so nobody picks one up expecting to write code.
