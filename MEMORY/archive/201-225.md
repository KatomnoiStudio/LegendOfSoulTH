## 202. The sprite table was already right; the two consumers that never read it were the bug

`aaf57b1` closes `#100` and `#106` together, and the interesting part is how small the fix turned out
to be once the standard existed.

**`E3` did the work before the code did.** Locking "world size is DERIVED from texture pixels, never
hand-authored" (`a178e8e`, cited to Unity `Sprite.pixelsPerUnit` and Godot `SpriteBase3D.pixel_size`)
reclassified the task from *design a mechanism and tune numbers* to *extend a table that already
exists to the consumers that never read it*. The reclassification held: the fix is a 6-line exported
`deriveSpriteSize()` plus five measured calibration rows. `entitySpritePresentation.ts` had been
running the international convention under a local name since before the lock was written —
`pixelsPerCanonicalHeight` is `pixelsPerUnit`, `bottomInsetPx` is the per-sprite pivot `E1` demands,
in the same record. **23 families registered now, up from 18.**

**What changed at the two sites.** `LobbyScene/CharacterModel.tsx` lost all three hand-typed
`planeGeometry args={[4.018, 3.213]}`; the scene now types one number, `LOBBY_SPRITE_HEIGHT = 3.213`,
and the `<group position={[0, 1.393, 0]}>` wrapper is gone because each mesh's own y puts its feet on
`y=0`. `AdventureScene/WukongAdventure.tsx` no longer lets `object-fit: contain` decide size. The
worst single site was the one nobody had counted: Tripitaka's halo, a 1194x1317 **portrait** sheet
pinned to a 1.2505 **landscape** plane — 37.9% stretch, and no `L1` provenance row anywhere.

| | before | after |
| --- | --- | --- |
| size spread — monkey / pigsy / erlang / tripitaka | 75.1 / 64.1 / 46.8 / 8.0 % | 0.03 / 0.55 / 0.09 / 0.02 % |
| lobby idle-to-action pop | 27.4 / 31.8 / 7.4 % | 0.18 / 0.16 / 0.03 % |
| declared feet, 10 families | 386.1-408.8 | **356.0000** |
| true-alpha feet | 22.7 px band, 30-53 px *below* the anchor | 2.16 px band around it |

**Three things worth keeping, none of which are the numbers.**

**(1) An independent re-measurement is cheap, and it paid.** This dispatch re-derived every figure the
blocked dispatch had produced — all eight turnaround values, the four size spreads, the 1.091x upscale
— with its own alpha scan, and reproduced them to the unit. It also rediscovered the normalisation
rule on its own by reproducing a registered row exactly. That is why a fresh agent could safely trust
a design it had not done. Re-measuring is the cheapest form of trust available.

**(2) The cost got reported, not buried.** Deriving size makes walk frames render at 93% of source
instead of 53%, so the resolution floor got *worse* — and the conformance record says so in a table.
The stated 3.40x at DPR 3 turned out to be **unreachable today**, because the 1.091x upscale belongs
to `spear-warrior-stop-turn` and the adventure scene filters to characters with walk frames, which
erlang and tripitaka do not have (`walkKits.ts`, `walkPrefix: null`). Worst *reachable* floor is
2.68x -> 2.89x, every reachable state still a downscale. The 3.40x arrives the day erlang gets his
other seven directions. **A fix that lists only what improved is a fix nobody can audit.**

**(3) The mutation-proof discipline found a gap it was not looking for.** Six proofs ran red-then-green
with SHA-verified byte-identical restores. A seventh mutation was injected and stayed **green**:
re-adding `inset: 0` to `.sprite` un-anchors the feet, because the inline `width`/`height` win but
`inset`'s `top: 0` over-constrains and defeats the inline `bottom` — and jsdom never evaluates CSS
Modules, so no test can see it. Disclosed in the conformance record's FUTURE section rather than
quietly left, alongside two siblings: nothing asserts `CharacterModel`'s geometry (no WebGL context in
tests), and nothing stops a *new* consumer from typing its own numbers.

**The gate that was added cannot pass by agreeing with itself.** Invariant 5 in
`src/game/spriteContract.test.ts` (22 tests now, was 18) compares the **declared table against
alpha-measured art**, not against another constant — the precise defect class this project was burned
by four times the same day. Band 2%, labelled Layer C; measured worst 0.86%. All four pre-existing
`KNOWN_FAILING` exception rows still measure exactly what they recorded.

**Left deliberately unfixed, and named:** three registered `bottomInsetPx` read ~2 px shallower than
the art (`monkey-v2-idle` 11 vs 13, `monkey-v2` 34 vs 36, `monkey-walk` 62 vs 63.72; erlang and pigsy
agree exactly). Changing them moves the battle scene — a different topic on the same table, and rule
16's one-topic discipline says it is not this dispatch's to take. It is the entire residual: feet land
1.6-1.7 px above the anchor instead of on it, consistently.

**Nothing here was observed in a browser.** The `+81.5%` and the knee-height shadow were MEASURED-LIVE;
their fix is arithmetic over an alpha scan, and it is labelled that way. `npm run ci` fully green —
1119 tests / 121 files, verified independently by main rather than taken from the dispatch's report.
